Equipment rental desk

Short exercises on one small equipment rental database. You solve three examples together in class. Then you write two blocks of code on your own. Four more exercises are for practice at home.

Shared database

Equipment rental

The rental desk rents cameras, lights and audio equipment to members. A row in the equipment table is a type of equipment, not one physical unit. A rental belongs to one member and can have several items. A member can have no rentals, and an equipment type can be in no rental. The desk also keeps inactive members and equipment that is no longer offered. Their history stays in the database.

Understanding the data

Each member has a name, an email address and the flag IsActive. The email address is optional, so it can be NULL. IsActive = 0 means that the member is inactive.

Each equipment type has a daily rate, a purchase price, AvailableQuantity and MinimumQuantity. AvailableQuantity is the number of units that are ready to rent. It is a given number: do not calculate it from the rentals. MinimumQuantity is the target for ready units. PurchasePrice is the cost of buying one more unit. IsActive = 0 means that the desk no longer offers the equipment.

Each rental stores the start date, the number of days (RentalDays) and the status: Reserved, CheckedOut, Returned or Cancelled. CheckedOut means that the member has the equipment and has not returned it. Returned means that the member returned the equipment and the rental is finished.

Each rental item has the key (RentalID, LineNumber), an equipment type and a quantity. The same equipment type can be on several items of one rental. Rentals 2013 and 2016 have no items on purpose. All amounts are in PLN. Ignore VAT.

Test cases in the exercises use these records on purpose: inactive member 3, member 6 with no email address and no rentals, a cancelled rental, and inactive equipment 550.

How to work

  1. Run rental_setup.sql once in your practice database. Run it again to get the initial data back. Check the row counts: Members 6, Equipment 7, Rentals 16, RentalItems 21.
  2. Declare the input values at the top of your block. Change them to test other cases.
  3. Use PRINT for messages. Read them in the Messages tab.
  4. Run the whole block each time, not a single line.
  5. Compare your output with the test cases below each exercise. Use the same words and the same numbers.
  6. No example or exercise changes the data in the rental tables.

You solve the three examples together in class. Then solve Exercise 1 and Exercise 2 on your own. Exercises 3 to 6 are for practice at home.

Exercise 4 · Rental desk

Three days of rentals

Use in this exercise

Input and rules: declare @StartDate DATE. If it is NULL, show a message and stop. Do not change any data.

Client brief

The rental desk reviews three days in a row, beginning with @StartDate. For each day count the rentals that start on that day and have a status other than Cancelled. Count rentals with no items too.

  • 2 rentals or more: the day is BUSY.
  • 0 or 1 rental: the day is QUIET.

Show one result for each of the three days, also when the count is 0. Each result has one row with these columns: RentalDay (the day), RentalCount (number of rentals) and DayType (BUSY or QUIET). Count a rental only on its start date. Do not count every day of a longer rental.

Hint: steps
  1. Check the start date. Missing? Show a message and stop.
  2. Set the day to the start date and a counter to 1.
  3. Repeat while the counter is 3 or less.
  4. Count the rentals that start on the day and are not cancelled.
  5. 2 or more? The day is BUSY. Otherwise QUIET.
  6. Show the row of the day.
  7. Move to the next day and add 1 to the counter.
